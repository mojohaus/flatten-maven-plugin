Usage

Simply add the plugin to the build section of your top-level POM as following.

<build>
  <plugins>
    ...
    <plugin>
      <groupId>org.codehaus.mojo</groupId>
      <artifactId>flatten-maven-plugin</artifactId>
      <version><!-- latest release --></version>
      <configuration>
      </configuration>
      <executions>
        <!-- enable flattening -->
        <execution>
          <id>flatten</id>
          <phase>process-resources</phase>
          <goals>
            <goal>flatten</goal>
          </goals>
        </execution>
      </executions>
    </plugin>
  </plugins>
</build>

NOTICE

The flattened POM is written to the build directory (target/.flattened-pom.xml), so mvn clean removes it. Versions before 1.10.0 wrote it next to the pom.xml; after an upgrade, delete that leftover file once. To keep the old location, set the parameter outputDirectory to the project base directory and bind the goal flatten:clean to remove the file.

The generated flattened POM will be set as POM file to the current project only for projects with packaging other than pom. You may want to also do this for pom packaging projects by setting the parameter updatePomFile to true.

If flattenMode is set to bom or resolveCiFriendliesOnly, or to byPackaging on a pom packaging project, the generated flattened POM will be set as a project POM file also for pom packaging.

Setting generated flattened POM as a project POM file will allow to install/deploy the generated POM instead of actual project POM file.

Keep developer information

If you want to keep additional development information in your POM you can configure predefined modes via the flattenMode parameter. For typical open-source-projects you can choose “oss”. To keep all additional POM elements and flatten only to a bare minimum use “resolveCiFriendliesOnly”. Here is an example configuration:

<configuration>
  <flattenMode>resolveCiFriendliesOnly</flattenMode>
</configuration>

Choose the mode by packaging

A shared parent often has two kinds of descendants. Parent POMs must keep the build and management their own children inherit, which calls for “resolveCiFriendliesOnly”. Artifacts such as jars are better served by a minimal consumer POM, which “defaults” produces. The mode “byPackaging” picks per project: “resolveCiFriendliesOnly” for pom packaging and “defaults” for every other packaging. Configured once in the shared parent, it spares each descendant from overriding the mode.

<configuration>
  <flattenMode>byPackaging</flattenMode>
</configuration>

As with “resolveCiFriendliesOnly”, a pom packaging project then installs and deploys its flattened POM without setting updatePomFile.
